# План EDA


## Часть 1: SPML Chatbot Prompt Injection Dataset

### 1.1 Обзор датасета
- **Источник**: [ArXiv paper "SPML: A DSL for Defending Language Models Against Prompt Attacks" (2024), репозиторий reshabhs/SPML_Chatbot_Prompt_Injection на Huggin Face](https://huggingface.co/datasets/reshabhs/SPML_Chatbot_Prompt_Injection)
- **Тип данных**: Текстовые данные
- **Поля**:
  - `system_prompt` — системный промпт чатбота
  - `user_prompt` — пользовательский ввод
  - `prompt_injection` — бинарный флаг (1 = атака, 0 = без атаки)
  - `degree` — интенсивность атаки
  - `source` — источник техники атаки

### 1.2 Задачи EDA

#### Базовая статистика
-  Общее количество записей
-  Распределение классов
-  Статистика по `degree` (min, max, mean, median, квантили)
-  Уникальные значения `source` и их частота
-  Длины `system_prompt` и `user_prompt` (символы, слова, токены)

#### Анализ системных промптов
-  Количество уникальных `system_prompt`
-  Тематическое разнообразие
-  Длина и сложность инструкций
-  Наличие правил/ограничений в системных промптах

#### Анализ пользовательских промптов
-  Сравнение длины benign и malicious промптов
-  Лексическое разнообразие
-  Частотный анализ n-грамм для каждого класса
-  Наличие специфических маркеров инъекций

#### Анализ атак
-  Распределение `degree` по `source`
-  Корреляция `degree` с длиной `user_prompt`
-  Примеры атаки для каждого `degree` и `source`

#### Визуализации
-  Bar plot: распределение классов
-  Histogram/boxplot: `degree` по классам и источникам
-  Scatter: длина user_prompt и degree
-  Heatmap: source и degree
-  Word clouds для benign и malicious промптов

#### Проверка качества данных
-  Дубликаты
-  Пропущенные значения
-  Несогласованности (degree > 0 но prompt_injection = 0 и наоборот)
-  Аномально короткие/длинные промпты

## Часть 2: TurnBench - Dev Set

### 2.1 Обзор датасета
- **Источник**: [Mundo AI, репозиторий `mundo-ai/turn-benchmark-dev` на Hugging Face](https://huggingface.co/datasets/mundo-ai/turn-benchmark-dev)
- **Тип данных**: Аудио (FLAC 48kHz, моно) + аннотации turn-taking
- **Объем**: 38 разговоров, ~7.3 часа аудио
- **Структура**: Одна строка = один разговор, два аудиопотока + 3 аннотатора на спикера

### 2.2 Задачи EDA

#### Базовая статистика датасета
-  Количество разговоров
-  Общая длительность аудио
-  Длительность на разговор (min, max, mean, median)
-  Распределение `conversation_type` из `metadata`
-  Баланс спикеров

#### Анализ аудио
-  Проверка sampling rate
-  Проверка моно/стерео
-  Амплитудная статистика
-  Процент речи и тишины
-  Спектральные характеристики

#### Анализ аннотаций (turn-taking events)
-  Общее количество событий на разговор / на спикера
-  Распределение типов меток (`label`): end-of-turn, interruption, backchannel и др.
-  Длительность событий (end_s - start_s)
-  Межаннотаторское согласование (IAA): Cohen's kappa / Fleiss' kappa между 3 треками
-  Согласованность таймстемпов между аннотаторами
-  Распределение событий во времени (начало/середина/конец разговора)

#### Взаимосвязь аудио и аннотаций
-  Акустические признаки в окрестностях границ turn, например: pitch, energy, pause duration
-  Корреляция длительности паузы с типом перехода
-  Анализ перекрытий: когда оба спикера говорят одновременно

#### Проверка качества и консистентности
-  Временная выравненность speaker_1_audio и speaker_2_audio
-  Полнота аннотаций (пустые треки `[]`)
-  Соответствие `metadata` реальным данным
-  Проверка на артефакты в аудио
-  Валидация корректности и логичности событий

#### Визуализации
-  Timeline визуализация: волны формы + аннотации для 2-3 разговоров
-  Histogram: длительность разговоров
-  Bar plot: распределение типов `label`
-  Boxplot: длительность событий по типам
-  Scatter: pause duration vs transition type

## Общие рекомендации по выполнению EDA

1. **Воспроизводимость**: зафиксировать random seeds, сохранить все промежуточные артефакты
2. **Документирование**: вести журнал наблюдений и гипотез в процессе анализа
3. **Модульность**: оформить каждый блок анализа как отдельный раздел в ноутбуке EDA
4. **Валидация**: проверить гипотезы на небольшой выборке
5. **Выводы**: сформулировать 3-5 ключевых инсайтов на датасет для последующего моделирования
